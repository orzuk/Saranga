# Silver corpus — all LLM-extracted papers, organized

This is the **single in-repo home** for every *silver* (LLM-extracted) paper in
Saranga. It replaces the previous scattered layout (an external symlinked pool +
`portal/data/tier2*`). Nothing here is generated by hand — regenerate it with
the two builder scripts (see *Rebuilding*).

## Layout

```
corpus/silver/
  metadata.csv                 # ← the ONE index: a row per extraction (all provenance)
  README.md
  <model>__<prompt>/           # one dir per extraction configuration
    prompt_opus_<ver>.md       #   the verbatim prompt used for every JSON here
    paperNNN.json ...
  tex/paperNNN.tex             # source LaTeX, one per paper identity
```

Organization is **by model + prompt** — each top-level subdirectory is one
extraction configuration and carries the prompt file that produced it:

| Directory | Papers | Prompt file | Meaning |
|---|---|---|---|
| `opus-4.7__v3_combined/` | 268 | `prompt_opus_v3_combined.md` | old "pool" extraction |
| `opus-4.8__v4.1/` | 74 | `prompt_opus_v4.md` | v4.1 train + test |
| `opus-4.7__v4.1/` | 3 | `prompt_opus_v4.md` | 3 train JSONs tagged opus-4.7 |
| **`opus-5__v5.1/`** | **100** | **`prompt_opus_v5.1.md`** | **current uniform corpus — see below** |

- The directory reflects each JSON's **actual** `metadata` (model + prompt), not
  what any email claimed — so mislabeled files sort honestly. Model tokens drop
  the redundant `claude-` prefix.
- **`v3_combined_with_steps` is folded into `v3_combined`.** That suffix was only
  an early explicit label (on `paper001–009`) for the same step-decomposition
  config later runs tag plainly `v3_combined`; both contain `proof_step`/
  `algorithm_step` nodes. The original label is preserved in the
  `prompt_version_raw` column.

## `opus-5__v5.1/` — the current uniform corpus (100 papers)

The corpus to use for new work. Every paper here was extracted with
**`claude-opus-5[1m]`** under **one frozen prompt**, `prompt_opus_v5.1.md`
(sha256 prefix **`100e6cf6fdbb3aea`**, verified unchanged before every launch).
Uniformity was the design constraint: an earlier partial run was discarded and
re-done from scratch rather than mixing two prompt revisions.

- **Filenames are `<arxiv_id>.json`** here (e.g. `1104.0194v1.json`), not
  `paperNNN.json` — this corpus is keyed by arXiv id, sampled fresh rather than
  inherited from the old pool.
- **Sampling:** 5 papers x 20 arXiv categories, drawn from the 1000-paper pool in
  `extraction_targets_opus5.csv`. The pool deliberately carries **no split
  column** — train/test is assigned later so the split can be redrawn.
- **Schema additions in v5.1:** definition decomposition
  (`definiendum`/`genus`/`differentia`) and `confidence` on both nodes and edges.

**Quality (full report: `CORPUS_REPORT_100.md`):**

| metric | value |
|---|---|
| nodes / edges | 12,817 / 21,601 |
| nodes per paper | mean 128.2, **median 104** |
| verbatim fidelity | **99.96%** (12,812/12,817 traced to source) |
| genuine fabrication | **2 nodes = 0.016%** |
| integrity failures | **0** — all valid, acyclic, endpoints resolve |
| mis-sliced spans | **0** of 14 boundary-spanning statements |

**Read before using this data:**

- `confidence` scores the *extraction judgment*, not mathematical rigor, and is
  **not comparable across papers** (no shared rubric anchor).
- Use the **median** for per-category comparison — n=5 cells are dominated by
  single large papers (`math_AT` mean 251 vs median 169).
- `category` in the pool CSV is the **sampled** category, not the arXiv primary;
  30/100 differ (`true_categories.csv`, ROADMAP 7.5.1).
- `rigor` is missing from ~95% of nodes: declared universal in `node_types.py`
  but never requested by the prompt (issue E130).
- Some real dependency edges were dropped to preserve acyclicity, notably
  induction hypotheses (issue E120). This is **not** post-hoc detectable.

Known issues are catalogued in `scripts/opus_extract_prompt_v6_TODO.md` (137
items). The high-severity ones are **spec defects, not model failures** — the
prompt contradicts itself and `src/*_types.py` in several places, and the corpus
faithfully inherited both sides of each disagreement.

## Paper identity, versions, and splits

`paperNNN` is a **stable paper identity**. The *same* paper is often extracted by
more than one model/prompt (e.g. an old `v3` pool extraction **and** a newer
`v4.1` train/test extraction). Those are **separate rows** — one per extraction —
and that duplication is intentional.

The train/test/pool **split lives in `metadata.csv`, not in the directory tree**:

| split | count | what it is |
|---|---|---|
| `pool` | 268 | the legacy `v3` set (opus-4-7); superset of everything below |
| `train` | 17 | v4.1 papers used for rule **distillation** (`paper001–016` + `paper450`) |
| `test`  | 60 | held-out v4.1 benchmark: 40 `A_matched_ML` + 20 `B_math_shift` |

Every train/test paper is *also* present as a `pool` row (its older `v3`
extraction). Total: **345 extractions across 268 distinct papers.**

## metadata.csv columns

`paper_id, arxiv_id, arxiv_source, arxiv_match_score, split, test_idx, tier,
model, prompt_version, prompt_version_raw, prompt_file, extraction_date,
annotator, primary_category, all_categories, published, title, short_name,
topic, n_nodes, n_edges, json_path, tex_path, has_tex`

- `prompt_version` is the canonical/folder version; `prompt_version_raw` is the
  exact string from the JSON metadata (differs only for the 8
  `v3_combined_with_steps` papers). `prompt_file` points at the source prompt in
  `scripts/`.

- `test_idx` (`T01`–`T60`), `tier` (`A_matched_ML`/`B_math_shift`), `short_name`,
  `topic` are populated for `test` rows (from the original test manifest).
- `arxiv_source` records **how** the id was obtained: `test_manifest`,
  `json_metadata`, `title_search`, or blank (unresolved). For `title_search`,
  `arxiv_match_score` is the fuzzy title-match confidence; only matches ≥ 0.90
  are accepted (below that the id is left blank — many old "pool" papers are
  pre-arXiv classics with no arXiv version, e.g. Shannon 1948, EM 1977).
- `n_nodes`/`n_edges` are counted from each JSON (supports both the `nodes/edges`
  and the legacy `objects/relations` schema).

## Provenance / how these were extracted

- **v4.1** (train + test): in-session agentic extraction driven by
  `scripts/in_session_extract_prompt.md`, which renders
  `scripts/opus_extract_prompt_v4.md`. Model: Claude Opus 4.8 (a few early train
  JSONs are tagged 4.7). Verbatim, no-prior-knowledge discipline.
- **v3_combined** (pool): earlier extraction, Claude Opus 4.7,
  `scripts/opus_extract_prompt_v3_combined.md`, dated 2026-05-01.

## Rebuilding

```bash
python scripts/build_silver_corpus.py     # offline: copy + metadata.csv (uses arXiv cache if present)
python scripts/build_silver_arxiv.py      # network: fill missing arxiv_id by title (~3s/req)
python scripts/build_silver_corpus.py     # re-run to fold resolved arXiv ids into metadata.csv
```

Both builders are idempotent. Source-of-truth inputs: external
`$SARANGA_DATA_ROOT/tier2/` (pool), `portal/data/tier2/` (train),
`portal/data/tier2_test/` (test). Those originals are left untouched — this
corpus is a consolidated **mirror** and is now the canonical in-repo copy.

See `corpus/gold/README.md` for the parallel human-gold corpus.
