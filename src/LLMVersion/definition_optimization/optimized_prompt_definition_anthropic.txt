You are analyzing a mathematical paper written in LaTeX. Extract ALL mathematical definitions.

## STEP 1: Scan for custom environments
Before extracting, scan the preamble for \newtheorem declarations (e.g., \newtheorem{defn}{Definition}, \newtheorem{dfn}{Definition}, \newtheorem{mydef}{Definition}, etc.). Treat any such custom environment as equivalent to a standard \begin{definition}...\end{definition} block.

## STEP 2: Identify definitions from these sources

1. **Formal definition environments**: \begin{definition}...\end{definition} and any custom variants found in Step 1. Extract the ENTIRE environment contents.

2. **Labeled definitional passages**: Paragraphs or sections explicitly headed "Definition X.Y" or similar numbering patterns.

3. **Inline definitions**: Passages that introduce a NEW named mathematical concept using definitional language such as: "is defined as", "is defined by", "we define", "is called", "is said to be", "we call", "we say that", "we consider the following definition", "defined below", "defined to be". The concept being defined is typically highlighted via \emph, \textit, \textbf, or quotation marks.

4. **Equation-based definitions**: Passages where a new mathematical object, function, or quantity is formally defined through an equation or formula, accompanied by definitional language.

## STEP 3: Determine extraction boundaries — THIS IS CRITICAL

A single definition extraction must include the ENTIRE definitional passage as one unit:

- **Start boundary**: Begin at the first sentence that introduces the definition. Include introductory phrases like "We consider the following definition" or "Let us consider the map... defined by".

- **End boundary**: Continue through ALL of the following that are part of the same definitional block:
  - All consecutive sentences that define related or dependent concepts in the same paragraph
  - All displayed equations (\[...\], equation environments, align environments, etc.) that formalize what is being defined
  - "Thus", "Hence", "That is", or "i.e." clauses that provide equivalent formulations
  - Conditions, constraints, or clarifications (e.g., "where...", "for all...", "such that...")
  - Subsequent sentences in the same paragraph that define closely related companion concepts (e.g., if one sentence defines concept A and the next defines concept B as a variant of A, extract both together)

- **Do NOT split** a paragraph that defines multiple related concepts into separate extractions. If a passage defines a base concept and then immediately defines variants, extensions, or special cases thereof, extract it all as ONE definition.

- **Do NOT truncate** before reaching the end of the definitional content. When in doubt, include more rather than less.

## What does NOT count as a definition — do NOT extract:
- Temporary notation or variable assignments (e.g., "Let x = 3", "Put w := f(v)", "Set ε = 1/2") that merely fix values for a proof or computation without introducing a reusable named concept.
- Theorems, lemmas, propositions, corollaries, claims, remarks, examples, observations, or assumptions — even if they contain the word "define" incidentally.
- Mere descriptions of properties, characterizations, or restatements of known definitions.
- Algorithm descriptions, experimental setups, or model architectures UNLESS they appear within a formal Definition environment or use explicit definitional language to name a new mathematical concept.
- Passages that merely recall or cite a previously established definition without new definitional content.

## STEP 4: Format output

For each definition, extract:
- **name**: Short descriptive name for the concept(s) being defined
- **raw_latex**: Original LaTeX text, copied VERBATIM character-for-character from the source. Do NOT modify anything: preserve all math delimiters, macros, commands, comments (% lines), whitespace, and line breaks exactly as they appear.
- **clean_text**: "" (always empty string)
- **label**: Any \label{...} found within the definition, or null

Return a JSON array:
